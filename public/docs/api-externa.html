1. Introducción y propósito

La API Externa de AgroSantander 360 permite a sistemas de terceros autorizados consultar de forma segura y estructurada el registro de agricultores caracterizados por CONSULTORES Y OPERADORES AGROINDUSTRIALES S.A.S. (COA) en el departamento de Santander, Colombia.

Esta API es de solo lectura. No permite crear, modificar ni eliminar registros. Expone información de beneficiarios (agricultores), sus predios, el estado de avance del proceso de caracterización y los datos de la visita técnica.

⚠️ Uso confidencial La información expuesta por esta API contiene datos personales protegidos bajo la Ley 1581 de 2012. El consumidor se compromete a tratarla conforme a la política de tratamiento de datos personales de COA.

2. Autenticación

La API usa autenticación por API Key fija. Cada petición debe incluir el header X-API-Key con la clave asignada.

HeaderValorObligatorio
X-API-Key Clave entregada por COA ✓
Ejemplo de header X-API-Key: agro360_ext_yHJB9IKrQSJBuMsuXqrg0fYIAWTUJDKl
Seguridad La clave debe mantenerse confidencial. No incluirla en código fuente público ni repositorios. Si se compromete, contactar a COA para rotarla.
Si la clave es incorrecta o está ausente, la API responde con HTTP 401 Unauthorized.

4. Endpoints disponibles

GET /api/external/agricultores Lista paginada de agricultores con predio y estado

Es el único endpoint disponible en esta versión. Retorna los registros de caracterización con toda la información del agricultor, predio y visita técnica asociada.

5. Parámetros de consulta (Query Params)

Todos los parámetros son opcionales. Sin parámetros, retorna todos los registros paginados.

Parámetro Tipo Descripción Ejemplo
estado string Filtra por estado del formulario. Acepta uno o varios separados por coma. APROBADO o REVISADO,APROBADO
fecha_desde string (fecha) Retorna solo registros cuya visita técnica fue en o después de esta fecha. 2026-01-01
fecha_hasta string (fecha) Retorna solo registros cuya visita técnica fue en o antes de esta fecha. Incluye todo el día (hasta las 23:59:59). 2026-05-31
municipio string Filtra por municipio del predio. Búsqueda parcial, insensible a mayúsculas y tildes. Bucaramanga
pagina integer Número de página a retornar. Inicia en 1. 2
limite integer Cantidad de registros por página. Mínimo 1, máximo 100. Default: 50. 25

Combinación de filtros

Los filtros son acumulativos (AND). Ejemplo: registros aprobados, en Bucaramanga, visitados en el primer trimestre de 2026:

GET /api/external/agricultores
    ?estado=APROBADO
    &municipio=Bucaramanga
    &fecha_desde=2026-01-01
    &fecha_hasta=2026-03-31
    &limite=100

La respuesta es un objeto JSON con dos propiedades raíz: data (array de registros) y paginacion.

      "fecha_registro":       "2026-03-15T10:30:00Z",
      "ultima_actualizacion": "2026-04-02T08:15:00Z",

      "agricultor": { /* Ver sección 7 */ },
      "predio":      { /* Ver sección 8 */ },

}

8. Campos del predio — descripción detallada

El predio es la unidad productiva visitada. Cada agricultor puede tener múltiples predios, pero el registro de caracterización siempre está asociado a uno específico.

CampoTipoUnidadDescripción
nombre string | null — Nombre del predio o finca. Ej: Finca La Esperanza.
departamento string — Departamento donde se ubica el predio. Actualmente siempre Santander.
municipio string — Municipio de Santander al que pertenece el predio. Ver lista de municipios en el Anexo.
vereda string | null — Nombre de la vereda o corregimiento donde está ubicado el predio.
direccion string | null — Dirección o descripción de acceso al predio.
tipo_tenencia string | null — Forma de tenencia del predio. Valores posibles: Propio, Arrendado, Comodato, Sucesión, Otro. Indica si el agricultor es dueño, arrendatario u otro tipo de tenedor.
area_total_ha decimal | null Hectáreas Área total del predio expresada en hectáreas. Incluye toda la extensión: productiva, bosque, vivienda, etc.
area_productiva_ha decimal | null Hectáreas Área dedicada a actividades agropecuarias productivas dentro del predio. Siempre es menor o igual a area_total_ha.
altitud_msnm decimal | null msnm Altitud del predio en metros sobre el nivel del mar (msnm). Dato relevante para determinar pisos térmicos, cultivos viables y condiciones climáticas.
Rangos orientativos en Santander: Cálido (<1.000 msnm), Templado (1.000–2.000), Frío (2.000–3.000), Páramo (>3.000).
latitud decimal | null Grados decimales Latitud geográfica del predio (WGS84). Rango en Santander: entre 5.5° N y 8.2° N. Puede ser el centroide del polígono o el punto marcado por el técnico.
longitud decimal | null Grados decimales Longitud geográfica del predio (WGS84). Rango en Santander: entre -74.5° W y -72.4° W. Valor negativo (oeste del meridiano de Greenwich).
cultivos_existentes string | null — Descripción libre de los cultivos presentes en el predio al momento de la visita. Puede incluir varios separados por coma. Ej: Cacao, Plátano, Café.

9. Estados del formulario — descripción y flujo

El campo estado refleja en qué etapa del proceso de evaluación se encuentra el formulario de caracterización de un agricultor. El flujo es progresivo y solo ciertos roles pueden mover un registro entre estados.

Diagrama de flujo de estados

  INICIADO ──► REVISADO ──► EN_ESTUDIO_CREDITO ──► APROBADO
                   │                                    │
                   └──────────────────────────────► CANCELADO

Descripción de cada estado

EstadoEtiqueta UIQuién lo asignaDescripción detallada
INICIADO Iniciado Sistema (automático) Estado inicial asignado automáticamente cuando el formulario de caracterización es sincronizado por primera vez con el servidor. Indica que el registro existe pero aún no ha sido revisado por ningún analista o administrador. Todos los formularios nuevos comienzan aquí.
REVISADO Revisado Asesor / Administrador El asesor de campo o un administrador ha verificado la información del formulario y la considera completa y válida. Es el primer estado que requiere acción humana. No implica aprobación de crédito, solo validación del formulario.
EN_ESTUDIO_CREDITO En estudio Analista / Administrador El caso ha sido enviado al área financiera/analistas para evaluar la viabilidad crediticia o de acompañamiento. En este estado se está analizando la información financiera del agricultor, el tamaño del predio y el sistema productivo.
APROBADO Viable Analista / Administrador El agricultor ha sido evaluado positivamente. Su perfil y predio son considerados viables para acceder a programas de acompañamiento técnico, financiero o crediticio de COA. Este es el estado final positivo del proceso.
CANCELADO No Viable Analista / Administrador El proceso fue cancelado o el agricultor fue evaluado como no viable para los programas actuales de COA. Puede deberse a información incompleta, predio fuera del área de cobertura, o perfil no apto para los productos disponibles. El agricultor puede presentar un nuevo formulario en el futuro.
SINCRONIZADO Sincronizado Sistema (legado) Estado de compatibilidad con versiones anteriores del sistema. Equivale funcionalmente a INICIADO. Registros antiguos pueden aparecer con este valor.
EN_REVISION En revisión Sistema (legado) Estado de compatibilidad. Equivale a REVISADO en versiones anteriores.
RECHAZADO Rechazado Sistema (legado) Estado de compatibilidad. Equivale a CANCELADO en versiones anteriores.
💡 Recomendación para consumidores Para consultar solo registros activos y vigentes, filtrar por los estados modernos: INICIADO,REVISADO,EN_ESTUDIO_CREDITO,APROBADO,CANCELADO. Los estados legado (SINCRONIZADO, EN_REVISION, RECHAZADO) corresponden a registros históricos.

10. Paginación

Todos los resultados están paginados. El objeto paginacion en la respuesta contiene la información necesaria para navegar entre páginas. 

"paginacion": {
  "total":      248,   // Total de registros que coinciden con los filtros aplicados
  "pagina":     1,     // Página actual
  "por_pagina": 50,    // Registros en esta respuesta
  "paginas":    5      // Total de páginas (ceil(248/50))
}

Para obtener todos los registros, iterar desde pagina=1 hasta paginas:

# Página 1
GET /api/external/agricultores?limite=100&pagina=1

# Página 2
GET /api/external/agricultores?limite=100&pagina=2

# ... hasta pagina = paginacion.paginas

JavaScript / Node.js (fetch)

const API_KEY = 'agro360_ext_yHJB9IKrQSJBuMsuXqrg0fYIAWTUJDKl'
const BASE    = 'https://agro-360.com/api/external/agricultores'

async function obtenerAgricultores(params = {}) {
  const qs = new URLSearchParams(params).toString()
  const res = await fetch(`${BASE}?${qs}`, {
    headers: { 'X-API-Key': API_KEY }
  })
  if (!res.ok) throw new Error(`HTTP ${res.status}`)
  return res.json()
}

// Todos los aprobados
const { data, paginacion } = await obtenerAgricultores({
  estado: 'APROBADO',
  limite: 100,
  pagina: 1
})
console.log(`Total: ${paginacion.total}`)
data.forEach(r => console.log(r.agricultor.nombres, r.predio.municipio))

Python (requests)

import requests

API_KEY = "agro360_ext_yHJB9IKrQSJBuMsuXqrg0fYIAWTUJDKl"
BASE    = "https://agro-360.com/api/external/agricultores"

headers = {"X-API-Key": API_KEY}

# Obtener todos los registros paginando
pagina, todos = 1, []
while True:
    r = requests.get(BASE, headers=headers, params={
        "estado": "APROBADO,REVISADO",
        "limite": 100,
        "pagina": pagina
    })
    r.raise_for_status()
    body = r.json()
    todos.extend(body["data"])
    if pagina >= body["paginacion"]["paginas"]:
        break
    pagina += 1

print(f"Total descargados: {len(todos)}")

13. Notas y limitaciones

  • Solo lectura: No existe ningún endpoint de escritura. La API no permite crear, modificar ni eliminar registros.
  • Un consumidor: La API key es única y personal. No debe compartirse ni usarse en sistemas públicos.
  • Sin rate limiting activo: En esta versión no hay límite de peticiones por minuto, pero se recomienda no superar 60 peticiones/minuto para no sobrecargar el servidor.
  • Fotos y firmas: Las URLs de fotografías del predio, del agricultor y la firma del productor no se exponen por esta API por razones de privacidad y tamaño.
  • Información financiera: Los datos de ingresos, egresos y activos del agricultor no se exponen por esta API.
  • Zona horaria: Todas las fechas con hora (fecha_registro, ultima_actualizacion) están en UTC (Z). Las fechas sin hora (visita.fecha, fecha_nacimiento) son solo fecha local.
  • Campos null: Los campos opcionales que no tienen valor retornan null (no se omiten del objeto).
  • Rotación de clave: En caso de comprometerse la API key, contactar a COA para obtener una nueva. La clave anterior quedará inválida de inmediato.
